# Результати спринта 1

## S-08. Розклад без інтернету

Як студент, я хочу бачити збережений розклад, коли зв'язку немає, щоб
користуватися застосунком у корпусі зі слабким сигналом (`SC-01`).

### Рішення

Розклад зберігається в локальній базі SQLite на смартфоні. Після кожного
успішного завантаження дані групи перезаписуються цілою транзакцією, тому
обрив зв'язку посеред оновлення не лишає половину розкладу.

Таблиці локальної бази:

| Таблиця | Поля |
| --- | --- |
| `lesson` | `id`, `group_id`, `weekday`, `start_time`, `end_time`, `subject`, `teacher_id`, `room` |
| `teacher` | `id`, `full_name`, `department`, `contact` |
| `sync_state` | `group_id`, `last_success_at`, `schedule_version` |

Стани застосунку щодо мережі:

| Стан | Умова | Що бачить користувач |
| --- | --- | --- |
| Онлайн | є мережа, оновлення успішне | розклад без позначки |
| Офлайн | мережі немає, локальна копія є | розклад і позначка «Офлайн» |
| Порожній офлайн | мережі немає, копії ще немає | повідомлення «Розкладу ще немає, під'єднайтесь до мережі» |

Фонова перевірка оновлень запускається, коли з'являється мережа: порівнюється
`schedule_version` на сервері з локальною, і лише при різниці завантажується
розклад.

```
┌──────────────────────────────┐
│ Група КН-42        [Офлайн]  │
├──────────────────────────────┤
│ Сьогодні, середа             │
│ 08:30  Менеджмент ІТ  ауд.214│
│ 10:10  Бази даних     ауд.108│
│ Оновлено: 2026-10-24 09:12   │
└──────────────────────────────┘
```

### Критерії приймання

| № | Якщо | То |
| :-: | --- | --- |
| A1 | розклад успішно завантажено хоча б раз | його збережено в локальній базі SQLite |
| A2 | телефон без мережі | застосунок відкривається без помилки, розклад видно, угорі позначка «Офлайн» |
| A3 | після офлайну з'явилась мережа | у фоні виконується перевірка оновлень без дій користувача |
| A4 | у фоні знайдено нову версію розкладу | локальні дані оновлено, позначка «Офлайн» зникає |

### Тест-кейси

| ID | Крок | Очікуваний результат | Критерій |
| :-: | --- | --- | :-: |
| TC-08-1 | завантажити розклад онлайн, закрити застосунок, вимкнути мережу, відкрити | розклад показано, є позначка «Офлайн» | A1, A2 |
| TC-08-2 | вперше відкрити застосунок без мережі | повідомлення «Розкладу ще немає, під'єднайтесь до мережі», без падіння | A2 |
| TC-08-3 | у режимі офлайн увімкнути мережу | протягом хвилини запускається перевірка оновлень | A3 |
| TC-08-4 | на сервері змінити розклад, увімкнути мережу | дані на екрані оновились, позначка зникла | A4 |
| TC-08-5 | вимкнути мережу посеред оновлення | лишається попередня копія, екран не порожній | A1, A2 |

### Граничні випадки

- Копія старша за тиждень: на екрані час останнього оновлення.
- Немає місця для запису в SQLite: попередня копія не стирається, помилка
  показується один раз.

## S-05. Розклад викладача

Як студент, я хочу подивитися розклад конкретного викладача, щоб знати, коли
його можна застати в корпусі (`SC-01`).

### Рішення

Пошук працює по таблиці `teacher` локальної бази з S-08, тому доступний і без
мережі. Автодоповнення спрацьовує від двох символів і шукає за початком
прізвища без урахування регістру. У підказці показуються прізвище з
ініціалами і кафедра, щоб розрізняти однофамільців.

Після вибору викладача запитом до `lesson` за `teacher_id` будується
розклад по днях тижня: день, час, аудиторія, група.

| Блок екрана | Джерело | Якщо даних немає |
| --- | --- | --- |
| Прізвище, ініціали | `teacher.full_name` | завжди є |
| Кафедра | `teacher.department` | блок прихований |
| Контакт | `teacher.contact` | блок прихований |
| Заняття по днях | `lesson` за `teacher_id` | «Занять цього тижня немає» |

```
┌──────────────────────────────┐
│ Пошук викладача:  [Ко___]    │
│   Коваленко О. І., ПІ        │
│   Ковальчук Р. П., КН        │
├──────────────────────────────┤
│ Коваленко О. І.              │
│ Кафедра програмної інженерії │
│ Пн  10:10  ауд.214  КН-42    │
│ Ср  08:30  ауд.108  КН-41    │
└──────────────────────────────┘
```

### Критерії приймання

| № | Якщо | То |
| :-: | --- | --- |
| B1 | студент вводить прізвище викладача в пошуковий рядок | з'являється список підказок з автодоповненням |
| B2 | студент обирає викладача | показано розклад занять по днях тижня з аудиторіями |
| B3 | у викладача вказано кафедру і контакти | вони показані під прізвищем; якщо їх немає, блок прихований |

### Тест-кейси

| ID | Крок | Очікуваний результат | Критерій |
| :-: | --- | --- | :-: |
| TC-05-1 | ввести три перші літери прізвища | список підказок, що починаються з цих літер | B1 |
| TC-05-2 | ввести прізвище, якого немає | «Викладача не знайдено», без падіння | B1 |
| TC-05-3 | обрати викладача з підказок | розклад по днях тижня з аудиторіями | B2 |
| TC-05-4 | обрати викладача без занять цього тижня | «Занять цього тижня немає» | B2 |
| TC-05-5 | обрати викладача з кафедрою і контактами | вони показані під прізвищем | B3 |
| TC-05-6 | обрати викладача без контактів | блок контактів прихований без порожніх рядків | B3 |

### Граничні випадки

- Два викладачі з однаковим прізвищем: у підказці ініціали і кафедра.
- Пошук без мережі працює по локальній копії.
