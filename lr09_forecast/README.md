## 2. Як рахувалася симуляція

| Поле | Значення |
| --- | --- |
| Інструмент | власний скрипт Python, `lr09_forecast/simulate.py` |
| Прогонів | 10000, зерно генератора 42, тож прогін повторюється |
| Що тягнеться випадково | `points_done` одного зі спринтів історії, з поверненням |
| Як рахується дата прогнозу | <останній день спринта, на якому закінчується робота: для сценарію «весь перший реліз» кінець спринта 1 плюс (P − 1) × 14 днів, для сценарію залишку кінець останнього спринта плюс P × 14 днів> |

Код лежить поруч, у `lr09_forecast/simulate.py`. Одна симуляція: беремо залишок
points і доки він більший за нуль, випадково тягнемо `points_done` одного зі
спринтів історії, віднімаємо від залишку й рахуємо спринт. Коли залишок
дійшов до нуля або нижче, записуємо кількість спринтів. Це 10000 разів,
результати сортуються, P50 і P85 беруться як `ceil(p × N)`-й елемент і
округлюються вгору до цілого спринта.

Запуск (історія velocity, обсяг, необов'язково номери спринтів через кому):

```
python lr09_forecast/simulate.py lr09_forecast/velocity.csv 50
python lr09_forecast/simulate.py lr09_reference_velocity.csv 220 5,6
```

Сам скрипт запускався в Docker-образі `python:3.11-slim`.
